## 一、Agent 核心概念

### 1.1 什么是 AI Agent

AI Agent 是运行在 Agentic AI 框架中的**自主软件体**，具备四大核心能力：

```
┌─────────────────────────────────────────────────────────┐
│                    AI Agent 核心能力                      │
├─────────────────────────────────────────────────────────┤
│                                                          │
│  ┌──────────┐  ┌──────────┐  ┌──────────┐  ┌──────────┐ │
│  │  推理规划  │  │   记忆    │  │  工具调用  │  │  自主执行  │ │
│  │Reasoning  │  │  Memory  │  │  Tools   │  │  Action  │ │
│  └──────────┘  └──────────┘  └──────────┘  └──────────┘ │
│                                                          │
│  能力说明:                                               │
│  - 推理规划: 分解复杂任务，制定执行计划                   │
│  - 记忆: 存储和检索历史信息与知识                         │
│  - 工具调用: 使用外部 API 和服务                          │
│  - 自主执行: 独立感知环境并采取行动                        │
│                                                          │
└─────────────────────────────────────────────────────────┘
```

### 1.2 Agent 与传统 AI 的区别

| 特性 | 传统 AI (Chatbot) | AI Agent |
|------|------------------|----------|
| 交互模式 | 单轮/多轮对话 | 持续任务执行 |
| 目标导向 | 回答问题 | 完成任务 |
| 工具使用 | 无 | 丰富的工具生态 |
| 记忆能力 | 有限对话历史 | 长期/短期记忆系统 |
| 自主性 | 被动响应 | 主动规划执行 |

## 二、推理架构模式

### 2.1 ReAct (Reasoning + Acting)

**原理**: 结合思维链推理与外部工具调用

```python
# ReAct 模式示例
Thought: 用户想要搜索相似的 3D 螺栓零件
Action: 调用 search_3d_model 工具
Observation: 找到 5 个相似零件，相似度 > 0.85
Thought: 需要进一步过滤材质属性
Action: 调用 filter_by_material 工具
Observation: 过滤后剩余 2 个不锈钢零件
Thought: 可以返回结果
Action: 返回最终答案
```

**优势**:
- 推理过程透明可追溯
- 错误可自我纠正
- 适合复杂任务分解

**适用场景**:
- 需要多步推理的任务
- 需要工具调用的场景
- 需要可解释性的场景

### 2.2 Plan-and-Solve

**原理**: 先制定完整计划，再逐步执行

```
Planning Phase:
┌─────────────────────────────────────┐
│ 任务: 为用户推荐相似的 CAD 零件      │
│                                     │
│ Plan:                               │
│ 1. 理解用户输入（零件类型/特征）     │
│ 2. 提取 3D 特征向量                 │
│ 3. 向量检索相似零件                 │
│ 4. 过滤不匹配的属性                 │
│ 5. 排序并返回 Top-K 结果            │
└─────────────────────────────────────┘

Solving Phase:
执行 Plan 中的每个步骤...
```

**优势**:
- 任务结构清晰
- 易于并行执行
- 便于进度跟踪

### 2.3 Chain-of-Thought (CoT)

**原理**: 通过中间推理步骤增强复杂问题解决能力

```
Question: 这个零件可以用什么替代？

Thinking Process:
1. 分析零件特征: M6 螺栓，长度 30mm，材质不锈钢
2. 确定关键参数: 螺纹规格、长度、强度等级
3. 搜索兼容零件: 相同螺纹规格，长度误差 ±5mm
4. 评估替代性: 强度等级 ≥ 8.8
5. 推荐结果: [零件列表]
```

### 2.4 Reflection (反思模式)

**原理**: Agent 自我评估和改进响应

```python
class ReflectiveAgent:
    def respond(self, query):
        # 初始响应
        initial_response = self.generate(query)

        # 自我评估
        critique = self.evaluate(initial_response)

        # 改进响应
        if critique.score < 0.8:
            improved_response = self.refine(initial_response, critique)
            return improved_response
        return initial_response
```

## 三、多 Agent 协作模式

### 3.1 监督者模式 (Supervisor Pattern)

**架构**: 中央协调者分配任务给专业 Agent

```
                    ┌──────────────────┐
                    │   Supervisor     │
                    │   Agent          │
                    │  (协调者)         │
                    └────────┬─────────┘
                             │
              ┌──────────────┼──────────────┐
              ▼              ▼              ▼
        ┌──────────┐   ┌──────────┐   ┌──────────┐
        │  Search  │   │   RAG    │   │Process   │
        │  Agent   │   │  Agent   │   │  Agent   │
        │(搜索专家) │   │(知识库)   │   │(处理)    │
        └──────────┘   └──────────┘   └──────────┘
              │              │              │
              └──────────────┴──────────────┘
                             │
                    返回结果给 Supervisor
                             │
                         汇总响应
```

**优势**:
- 清晰的责任分工
- 易于扩展新 Agent
- 中心化的流程控制

**适用场景**:
- I3D 系统的 5 个微服务协调
- 需要明确任务分配的场景

### 3.2 层次化模式 (Hierarchical Pattern)

**架构**: 多层监督结构

```
                ┌──────────────────────────────────┐
                │      Root Supervisor             │
                │      (根协调者)                   │
                └────────────┬─────────────────────┘
                             │
        ┌────────────────────┼────────────────────┐
        ▼                    ▼                    ▼
┌───────────────┐   ┌───────────────┐   ┌───────────────┐
│ Domain A      │   │ Domain B      │   │ Domain C      │
│ Supervisor    │   │ Supervisor    │   │ Supervisor    │
│(3D 搜索域)     │   │(知识库域)      │   │(文件处理域)    │
└───────┬───────┘   └───────┬───────┘   └───────┬───────┘
        │                   │                   │
   ┌────┴────┐         ┌────┴────┐         ┌────┴────┐
   ▼         ▼         ▼         ▼         ▼         ▼
Agent1    Agent2    Agent3    Agent4    Agent5    Agent6
```

**优势**:
- 支持复杂域划分
- 可扩展性强
- 符合企业组织结构

### 3.3 对等网络模式 (Peer-to-Peer Mesh)

**架构**: Agent 之间直接通信

```
    ┌─────────┐
    │ Agent A │◄────┐
    └────┬────┘     │
         │          │
    ┌────┴────┐     │
    │         │     │
┌───▼───┐ ┌──▼────▼──┐ ┌───┐
│Agent B │─│  Agent C │─│...│
└───────┘ └──────────┘ └───┘
    │         │
    └─────────┘
       直接通信
```

**优势**:
- 去中心化
- 高容错性
- 低延迟

**适用场景**:
- 需要高可用的场景
- Agent 间需要频繁交互

### 3.4 辩论模式 (Debate Pattern)

**架构**: 多个 Agent 提出不同观点，最终达成共识

```
        ┌─────────────────────────────────────┐
        │              用户问题                │
        └─────────────┬───────────────────────┘
                      │
        ┌─────────────┼─────────────┐
        ▼             ▼             ▼
   ┌─────────┐  ┌─────────┐  ┌─────────┐
   │Agent A  │  │Agent B  │  │Agent C  │
   │ 观点 1  │  │ 观点 2  │  │ 观点 3  │
   └────┬────┘  └────┬────┘  └────┬────┘
        │            │            │
        └────────┬───┴────────────┘
                 ▼
          ┌───────────┐
          │  仲裁者   │
          │(Arbiter)  │
          └─────┬─────┘
                │
           综合结论
```

### 3.5 黑板模式 (Blackboard Pattern)

**架构**: 共享状态空间，Agent 读写协同

```
        ┌─────────────────────────────────────┐
        │         黑板 (Blackboard)            │
        │    共享知识 / 状态空间               │
        └─────────────┬───────────────────────┘
                      │
        ┌─────────────┼─────────────┐
        ▼             ▼             ▼
   ┌─────────┐  ┌─────────┐  ┌─────────┐
   │Agent A  │  │Agent B  │  │Agent C  │
   │(专家1)  │  │(专家2)  │  │(专家3)  │
   └─────────┘  └─────────┘  └─────────┘
        │             │             │
        └─────────────┴─────────────┘
                     │
              读写黑板状态
```

### 4.2 记忆类型与实现

| 记忆类型 | 存储方式 | 检索方式 | 典型用途 |
|---------|---------|---------|---------|
| **语义记忆** | 向量数据库 | 语义相似度 | 知识库问答 |

## 五、工具与函数调用

### 5.1 函数调用最佳实践 (2025)

#### 工具设计原则

```yaml
命名规范:
  - 清晰描述性: search_similar_3d_models
  - 动作导向: extract_features, filter_results
  - 避免缩写: 不要用 srch_3d_mdl

描述规范:
  - 简洁: "搜索与给定3D模型相似的零件"
  - 包含用途: "用于在产品库中查找相似零件"
  - 说明约束: "仅支持 STEP/PRT 格式"

参数设计:
  - 必需参数明确标记
  - 提供合理默认值
  - 包含验证逻辑
  - 类型注解完整
```

#### 示例: I3D 工具定义

```python
tools = [
    {
        "name": "search_3d_model_by_image",
        "description": """
        使用2D图片搜索相似的3D CAD零件。
        支持上传截图或草图，系统将提取特征并在向量库中检索。
        """,
        "parameters": {
            "type": "object",
            "properties": {
                "image": {
                    "type": "string",
                    "description": "Base64编码的图片数据"
                },
                "file_type": {
                    "type": "integer",
                    "enum": [1, 2],
                    "description": "1=零件库, 2=产品库"
                },
                "top_k": {
                    "type": "integer",
                    "default": 10,
                    "description": "返回结果数量"
                }
            },
            "required": ["image", "file_type"]
        }
    },
    {
        "name": "filter_by_plm_attributes",
        "description": "根据PLM属性过滤搜索结果",
        "parameters": {
            "type": "object",
            "properties": {
                "material": {"type": "string", "description": "材质"},
                "weight_min": {"type": "number", "description": "最小重量"},
                "weight_max": {"type": "number", "description": "最大重量"}
            }
        }
    }
]
```

## 八、RAG 知识库架构

### 8.1 RAG 架构模式

```
┌─────────────────────────────────────────────────────────────────┐
│                       RAG 系统架构                               │
├─────────────────────────────────────────────────────────────────┤
│                                                                  │
```

### 8.2 高级 RAG 模式

#### Agentic RAG

Agent 主动决定检索策略：

```python
class AgenticRAG:
    def query(self, user_query):
        # Agent 分析查询
        analysis = self.analyze_query(user_query)

        # 动态选择检索策略
        if analysis.requires_global_view:
            context = self.global_retrieval(user_query)
        elif analysis.requires_specific_doc:
            context = self.targeted_retrieval(user_query)
        else:
            context = self.standard_retrieval(user_query)

        # 可能多轮检索
        if self.needs_more_info(context):
            context += self.additional_retrieval(user_query, context)

        return self.generate(user_query, context)
```

## 十一、向量数据库

### 11.1 pgvector (I3D 已集成)

**优势**:
- PostgreSQL 原生扩展
- 无需额外基础设施
- 与现有数据共同存储
- 支持 RLS 行级安全

**配置**:
```sql
-- 创建向量表
CREATE TABLE product_embeddings (
    tenant_id TEXT,
    item_code TEXT,
    embedding_type TEXT,
    embedding VECTOR(512),
    metadata JSONB,
    PRIMARY KEY (tenant_id, item_code, embedding_type)
);

-- 创建 HNSW 索引
CREATE INDEX ON product_embeddings
USING hnsw (embedding vector_cosine_ops);

-- RLS 策略
ALTER TABLE product_embeddings ENABLE ROW LEVEL SECURITY;
```

**性能**:
- 维度: 512 (I3D 标准)
- 索引: HNSW (M=16, ef_construction=64)
- 查询: 10-100ms (取决于数据量)

### 11.2 迁移/扩展选项

如果需要更高性能或更大规模：
